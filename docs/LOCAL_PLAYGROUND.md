# Локальная песочница

Редактируйте текст и смотрите четыре результата: найденные фрагменты, подмену,
точность обратного восстановления и восстановление собственного ответа.
Работают настоящие `detect`, `mask`, `restore` и SQLite vault.

## Запуск

Из корня репозитория, после установки зависимостей:

```bash
.venv/bin/python scripts/showcase.py
```

Откройте **http://127.0.0.1:8790**. Другой порт:

```bash
.venv/bin/python -m pii_gateway.web --port 8791
```

1. Оставьте синтетический пример или вставьте свой тестовый текст.
2. Выберите вымышленные значения или маркеры и нажмите «Заменить данные».
3. Сравните подмену с исходником; раскройте список найденных фрагментов.
4. Измените подставленный текст в «Попробуйте свой ответ» и восстановите его.

При ошибке обработка прекращается: старый результат очищается, симуляция не
подставляется. Неизвестные маркеры при восстановлении отмечаются как частичный
результат. Правки исходника или режима сбрасывают предыдущий результат.

## Что проверяет экран

- Реальную локальную обработку текущего текста и её время.
- Точное совпадение исходника с результатом `restore(mask(text))`.
- Восстановление известных замен в отредактированном ответе.

Экран **не вызывает LLM**, не отправляет запросы upstream и не проверяет сетевой
sandbox. Дословное совпадение не доказывает полноту детекции или сохранение
связей между людьми. Для сетевых проверок используйте [стенд](../bench/README.md).
Поддерживаемые входные форматы и границы MVP — в [приёмке](MVP_ACCEPTANCE.md).

## Локальная сессия

CLI слушает только `127.0.0.1`. На запуск создаётся новый приватный временный
каталог vault; существующий `PII_VAULT_DIR` не используется и не очищается.
Временный каталог удаляется при штатной остановке (`Ctrl+C`); после аварийного
завершения процесса временные файлы могут остаться до очистки ОС.
После перезапуска старые замены больше не восстанавливаются в этой сессии.

API защищён случайным токеном текущего процесса, проверками Host и Origin;
CORS не включён. Токен получает только страница с того же origin. Клиент не
может выбирать `project_id`, читать чужой vault или удалять его через API.
Данные не сохраняются в browser storage; ответы помечены `no-store`.
Это защита границы браузера, а не от вредоносных процессов того же пользователя.

Не запускайте factory `create_app` отдельно в рабочем gateway-процессе:
изоляция временного хранилища обеспечивается указанным CLI. Песочница использует
текущий движок проекта и наследует его ограничения; она не исправляет их сама.

## Проверки

```bash
.venv/bin/python -m pytest -q tests/web
.venv/bin/ruff check
```

Тесты проверяют настоящие roundtrip в обоих режимах, отказ фильтра, неизвестные
маркеры, токен, Origin/Host, недоступность чужих проектов и очистку собственного
временного vault. Все данные тестов синтетические.

Идея редактируемого текста и промежуточных этапов взята из закрытого
[PR #42](https://github.com/Punk2013/hack-msu/pull/42). Новая реализация
показывает только фактические локальные результаты.
