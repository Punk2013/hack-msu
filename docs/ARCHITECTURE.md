## 1. Обещание и границы

Обратимая псевдонимизация прямых идентификаторов в канале «агент ↔ LLM API».
Это не анонимизация: косвенные признаки и смысл документа модель видит.
До утверждения границы владельцем продукта работаем только на синтетических данных.

**Протокол [решено, Punk2013]: OpenAI Chat Completions** (`POST /v1/chat/completions`).
Это самый распространённый формат: его принимают OpenAI, DeepSeek, Mistral, OpenRouter, локальные
Ollama, llama.cpp и vLLM, а свой `base_url` с ним поддерживают многие агенты.
Адаптеры Anthropic Messages (Claude Code) и OpenAI Responses (Codex) — после MVP.
Ядро (§4) от протокола не зависит.

- **Клиент для демо [решено]:** OpenCode, если он проходит Gate 0 до 14:45 **[проверить]**.
  Запасной вариант без риска — свой минимальный агент `pii_gateway.demo_agent`
  (OpenAI SDK + инструменты `read_file`/`write_file`), его делает роль 1.
- **Upstream:** для разработки и тестов — локальная Ollama (бесплатно, без внешней сети).
  Для демо — облачный OpenAI-совместимый провайдер.
- **Сценарий:** агент читает `.txt`/`.md` с синтетическими клиентами и готовит уведомления.
- **Первый сквозной slice [решено]:** PERSON, EMAIL, PHONE, PASSPORT_RU. Затем ADDRESS, SNILS,
  INN, CARD, BIRTH_DATE.
- **Режимы замен [решено, Punk2013, 13:20]:** по умолчанию `realistic` — **выдуманные данные
  для всех типов**, чтобы агент не знал, что работает с обезличенными данными: склоняемые ФИО,
  email, телефон и паспорт в формате оригинала. `marker` (`[PERSON_1]`) — запасной вариант
  только там, где однозначный псевдоним подобрать нельзя, и режим для сравнения (§9).
  Отсутствие победителя сравнения не блокирует запуск.
- **Поиск:** regex с валидаторами и один NER, без локальной LLM.

- **Публичные лица [решено]:** автоматики нет. Если останется время (stretch) — ручной флаг
  `public` у сущности в vault: имя не заменяется. Паспорт, телефон, email и адрес не заменяются
  никогда только по флагу — для них исключений нет.

Не входит в MVP: Anthropic и Responses API, автоматическое определение публичных лиц, OCR и вложения,
полная автоматическая кореференция, глобальная таблица на все проекты.

## 3. Поток данных

**Запрос (агент → модель).** Gateway разбирает JSON по схеме протокола. Глобальной замены
в сериализованной строке нет. Каждое текстовое поле (§5) обрабатывается отдельно:
`detect()`, затем `mask()`. Диапазоны spans считаются внутри своего поля.

**Ответ (модель → агент).** Текст проходит `restore()`. Аргументы `tool_calls`
восстанавливаются только по политике tools (§6). Агент хранит у себя реальные данные.
На следующем ходу история снова проходит `mask()`.

**Детерминизм.** `mask()` зависит только от текста поля и состояния vault проекта.
Vault в рамках проекта только растёт, поэтому повтор истории даёт тот же результат.
Отдельный идентификатор диалога не нужен (в Chat Completions его нет).
Prompt caching провайдера при этом не ломается **[проверить]**.

**Отказ (fail-closed) [решено].** Ошибка `detect`, `mask` или vault, неизвестный тип части
сообщения, неподдерживаемый endpoint или параметр: запрос **не отправляется**.
Агент получает HTTP-ошибку с понятным текстом без ПДн. Режима обхода фильтра нет.

## 4. Контракт ядра [предложение]

Python 3.12. Индексы — Unicode code points, диапазон полуоткрытый `[start, end)`.
Инвариант: `text[start:end] == span.raw_text`.

```python
class PiiType(StrEnum):
    PERSON = "PERSON"; EMAIL = "EMAIL"; PHONE = "PHONE"; PASSPORT_RU = "PASSPORT_RU"
    ADDRESS = "ADDRESS"; SNILS = "SNILS"; INN = "INN"; CARD = "CARD"; BIRTH_DATE = "BIRTH_DATE"

@dataclass(frozen=True)
class Context:
    project_id: str                          # граница vault
    mode: Literal["marker", "realistic"]

@dataclass(frozen=True)
class EntitySpan:
    start: int
    end: int
    type: PiiType
    raw_text: str
    detector: str                            # "regex:passport_ru@1", "natasha@1.6"
    confidence: float | None = None          # None = не измерено
    grammemes: dict[str, str] | None = None  # {"case": "gent", "gender": "femn"}

# Роль 2. Spans не пересекаются и отсортированы по start.
# Пересечения разрешает detect: структурированный тип > NER, затем более длинный span.
# Checksum не сошлась → данные всё равно чувствительные (тип сохраняется).
def detect(text: str, ctx: Context) -> list[EntitySpan]: ...   # raises DetectError

@dataclass(frozen=True)
class Replacement:
    start: int; end: int              # диапазон в ВЫХОДНОМ тексте
    entity_id: str                    # uuid4 из vault, не ФИО
    linked_by: Literal["exact", "partial_single", "new"]
    form: str | None                  # граммемы формы, если склонялась

@dataclass(frozen=True)
class MaskResult:
    text: str
    replacements: list[Replacement]

# Роль 3.
def mask(text: str, spans: list[EntitySpan], ctx: Context) -> MaskResult: ...  # raises MaskError

class RestoreStatus(StrEnum):
    COMPLETE = "complete"   # все псевдонимы восстановлены, подозрительных нет
    PARTIAL = "partial"     # есть неразрешённые ссылки

@dataclass(frozen=True)
class Unresolved:
    start: int; end: int
    reason: Literal["unknown_marker", "unknown_form", "ambiguous_form"]
    # без исходного текста ПДн: в логи попадают только reason и диапазон

@dataclass(frozen=True)
class RestoreResult:
    text: str
    status: RestoreStatus
    unresolved: list[Unresolved]

def restore(text: str, ctx: Context) -> RestoreResult: ...
```

Правила связывания сущностей:

- **Ключ — `entity_id`, а не строка.**
- **Одинаковое полное значение → одна сущность в пределах проекта [решено, требование Punk2013;
  заменяет иную формулировку в Issue #11].**
  «Иван Иванов» во всех документах проекта получает один псевдоним. Для ФИО сравнивается нормальная
  форма (начальная форма каждой части). Ограничение: двое тёзок с одинаковым полным ФИО сольются.
  Это известное ограничение MVP. Сущность можно вручную разделить в просмотре таблицы
  **[предложение]**. Тест на двух тёзок фиксирует это поведение явно.
- **Неполное упоминание** («Иванов», «И. Иванов») связывается с полной сущностью, только если
  **в том же текстовом поле** ровно один подходящий кандидат (`linked_by="partial_single"`,
  видно в таблице). Иначе это новая сущность с флагом `ambiguous`.
- **Псевдоним (realistic):** тот же род и тот же тип склонения, что у оригинала.
  Соответствие форм «оригинал ↔ псевдоним» должно быть взаимно однозначным по всем падежам
  (контрпример «Саша Шевченко»). Если однозначности нет, генерируем другой; если не нашлось — marker.
- **Выдуманные структурированные данные (realistic):** `pseudo/fakes.py`. Формат оригинала
  сохраняется (разделители, `+7`/`8`, пробелы и переносы в паспорте), цифры заменяются, email —
  вымышленное имя на зарезервированном домене `example.test`. Значение детерминировано по
  `entity_id`, не совпадает с оригиналом и проверяется на коллизии в vault.
  Ограничение: если модель перепишет значение в другом формате (`+79000000001` вместо
  `+7 900 000-00-01`), обратная замена его не узнает.
  Псевдоним не совпадает ни с одним исходным значением в vault и в текущем тексте.
- **Restore** ищет только известные псевдонимы и маркеры проекта, ничего не угадывает.
  `PARTIAL` блокирует запись файла (§6) и помечается в UI.

## 5. Адаптер OpenAI Chat Completions (роль 1)

Поддерживаемые endpoint'ы: `POST /v1/chat/completions` и `GET /v1/models` (проксируется как есть).
Остальные (`/v1/responses`, `/v1/embeddings`, `/v1/completions`, ...) → отказ 404.

| Поле запроса | Действие |
| --- | --- |
| `messages[].content` (строка) у `system`, `developer`, `user`, `assistant`, `tool` | mask |
| `messages[].content[]` части `{"type": "text"}` | mask |
| части `image_url`, `input_audio`, `file` и неизвестные | **отказ** (MVP только текст) |
| `messages[].tool_calls[].function.arguments` (строка JSON) | parse → mask строковых значений рекурсивно → serialize. Невалидный JSON → отказ |
| `messages[].name`, `assistant.refusal` | mask |
| `tools[].function.description`, `description` в `parameters` | mask |
| прочие строки в `tools[].function.parameters` (`enum`, `default`, `examples`) | detect; нашлись ПДн → отказ |
| `n > 1`, `logit_bias`, `prediction` | отказ (в MVP не поддерживаем) |
| прочие параметры (`model`, `temperature`, `stream`, `tool_choice`, ...) | без изменений |

| Ответ | Действие |
| --- | --- |
| `choices[0].message.content`, `refusal` | restore |
| `choices[0].message.tool_calls[]` | parse `arguments` → политика §6 → serialize |
| стрим: `delta.content` | restore с буфером хвоста: задерживаем не больше `max_len(псевдоним)` символов и отдаём до последней границы слова |
| стрим: `delta.tool_calls[]` | копим фрагменты `arguments` по `index`; на `finish_reason` применяем §6 и отдаём каждый вызов одним delta |
| стрим: `delta.reasoning_content` (расширение провайдеров) | пропускаем без restore |
| `usage`, `[DONE]`, прочие поля | пропускаем |

Ошибки и ретраи провайдера передаются агенту как есть.

## 6. Политика tools [предложение]

Имена инструментов зависят от клиента, поэтому политика задаётся в конфиге gateway
для выбранного клиента. Неизвестный инструмент → класс `deny`.

| Класс | Восстанавливать аргументы | Условие |
| --- | --- | --- |
| `local_read` (чтение, поиск по файлам) | да | путь внутри workspace |
| `local_write` (запись, правка) | да | путь внутри `allowed_write_roots`; `restore` = `COMPLETE` |
| `shell` | **нет** | в MVP запрещён в агенте или ограничен allowlist в sandbox |
| `network` (fetch, search, MCP) | — | `deny` |
| `deny` | — | вызов блокируется |

**Блокировка — реальная, а не «просто без обратной замены» [решено].**
Если вызов нарушает политику, gateway **удаляет его из ответа** и отдаёт вместо него текст
ассистента «вызов `<имя>` заблокирован политикой» с `finish_reason: "stop"`.
Агент этот вызов не получает и выполнить не может. Дополнительно в поставке есть запрещающие
настройки самого агента (§8): защита в два слоя.

**Проверка пути** выполняется **после** restore и нормализации пути (`realpath`).
Symlink, ведущий за пределы разрешённой области, запрещён. Синхронизируемые облачные папки
в `allowed_write_roots` не входят.

## 7. Vault (роль 3)

- SQLite по пути `~/.local/share/pii-gateway/vault/<project_id>.db`, вне workspace, права `0600`.
  Каталог не монтируется в sandbox агента, включая файлы `-wal` и `-shm`.
- Таблицы (эскиз): `entity(entity_id, project_id, type, ambiguous)`,
  `surface(entity_id, side, form, text)` — формы оригинала и псевдонима,
  `audit(ts, event, entity_id, counts)` — без ПДн.
- Шифрование на диске — после MVP. В MVP защита держится на правах доступа и sandbox.
- Очистка: `purge(project_id)`.
- Кэш `mask` — только после замера задержки. Ключ кэша включает версию детектора,
  политику, `project_id` и ревизию vault.

## 8. Sandbox и поставка (роли 4 и 1)

- Агент запускается так, что из сети доступен только `host:port` gateway.
  Механизм (network namespace, bubblewrap и т. п.) выбирает роль 4 **[проверить]**.
- Агенту недоступны vault, конфиг и код gateway.
- Поставка: конфиг выбранного клиента (`base_url` на gateway, запрет shell и сетевых
  инструментов), скрипт запуска sandbox, команда просмотра таблицы.
- Ключ API провайдера хранится у gateway, а не у агента. Агент получает локальный токен gateway.

## 9. Gate и проверки

Сроки привязаны к расписанию хакатона (PROJECT.md).

**Gate 0 — протокол (до 14:45, только синтетика).** Gateway в режиме pass-through пишет
полные запросы и ответы в лог. Цель: выбрать клиента и увидеть, как он передаёт историю,
результаты инструментов, стриминг `tool_calls` и есть ли соединения мимо gateway.
Fail-closed этот gate **не** проверяет.

**Gate 1 — защита (до 16:30).** Masking включён. Проверяются:
1. сценарий «чтение → правка → новый файл → повторный ход» с восстановлением;
2. инъекция сбоя в `detect`: upstream spy (тестовый сервер на месте провайдера) подтверждает,
   что запрос **не пришёл**;
3. запрещённый вызов инструмента удалён из ответа (§6);
4. сетевая попытка из sandbox заблокирована, наблюдение независимо от лога gateway.

Если Gate 1 не проходит, сужаем обещание в Issue #4 до начала основной разработки.

**Метрики MVP:**

| Что | Как | Владелец |
| --- | --- | --- |
| Поиск | recall/precision по типам на размеченной синтетике, включая опечатки | 2 |
| Восстановление | `restore(mask(x)) == x`, плюс ответы, изменённые моделью: падежи, тёзки, неизвестные метки | 3 |
| Утечки | канарейки в исходящем трафике, наблюдение независимо от лога gateway | 4 |
| Полезность | marker vs realistic vs оригинал: одна задача, несколько запусков, правильность писем и число правок | 1 + 4 |
| Практичность | задержка на ход, пиковая RAM, размер vault | 1 |

Ноль утечек на тестовом наборе — результат конкретной проверки, а не доказательство отсутствия утечек.

## 10. Репозиторий и команды [предложение]

Пакет `pii_gateway`, Python ≥ 3.12, стандартный `pyproject.toml` (setuptools). Каркас — в PR bootstrap.

```
pyproject.toml
src/pii_gateway/
  core/types.py      # §4: общие типы (владелец роли 1)
  gateway/           # роль 1
  detect/            # роль 2
  pseudo/  vault/    # роль 3
  sandbox/           # роль 4
tests/<модуль>/      # тесты рядом по модулю
bench/               # синтетика и стенд (роль 4), без реальных данных
```

Команды (без обязательного uv):

```bash
python3 -m venv .venv && .venv/bin/pip install -e '.[dev]'
.venv/bin/pytest
.venv/bin/ruff check
```

Общие типы `core/types.py` меняет только роль 1. Зависимость своего модуля владелец добавляет
в `pyproject.toml` в своём PR (lock-файла нет).
