# Архитектура MVP: обезличивающий gateway для Claude Code

Статус: **черновик**, контракт не утверждён. Обсуждение: [Issue #4](https://github.com/Punk2013/hack-msu/issues/4).
Автор черновика: Punk2013 / Claude Code. Сводка вариантов — `docs/SOLUTION_DISCUSSION.md` (PR #6).

Пометки: **[решено]** — согласовано в Issue #4; **[предложение]** — ждёт ревью;
**[проверить]** — гипотеза, которую закрывает gate или тест.

## 1. Обещание и границы

Обратимая псевдонимизация прямых идентификаторов в канале «Claude Code ↔ Anthropic API».
Это не анонимизация: косвенные признаки и смысл документа модель видит.
До утверждения границы владельцем продукта работаем только на синтетических данных.

В MVP **[решено]**:

- один клиент: Claude Code, протокол Anthropic Messages (`POST /v1/messages`);
- сценарий: агент читает `.txt`/`.md` с синтетическими клиентами и готовит уведомления;
- типы данных: ФИО, адрес, паспорт РФ, СНИЛС, ИНН, телефон, email, номер карты, дата рождения;
- два режима замен: маркеры (`[PERSON_1]`) и правдоподобные склоняемые псевдонимы, со сравнением;
- поиск: regex с валидаторами и один NER, без локальной LLM.

Не входит: Codex (Responses API), Antigravity, публичные лица, OCR и вложения,
полная автоматическая кореференция, глобальная таблица на все проекты.

## 3. Поток данных

**Запрос (harness → модель).** Gateway разбирает JSON по схеме протокола. Глобальной замены
в сериализованной строке нет. Обрабатываются только известные текстовые поля (§5).
Для каждого поля выполняется `detect()`, затем `mask()`, затем запрос отправляется провайдеру.

**Ответ (модель → harness).** Текст проходит через `restore()`. Аргументы `tool_use`
восстанавливаются только по политике tools (§6). Harness хранит у себя реальные данные.
На следующем ходу они снова проходят `mask()`. Замены детерминированы
(одна сущность — один псевдоним), поэтому prompt caching провайдера не ломается **[проверить]**.

**Отказ (fail-closed) [решено].** Ошибка `detect`, `mask` или vault,
а также неизвестный тип блока или поля: запрос **не отправляется**.
Harness получает HTTP 4xx/5xx с понятным текстом без ПДн.
Режима обхода фильтра нет.

## 4. Контракт ядра [предложение]

Python 3.12. Индексы — Unicode code points, диапазон полуоткрытый `[start, end)`.
Инвариант: `text[start:end] == span.raw_text`.

```python
class PiiType(StrEnum):
    PERSON = "PERSON"; ADDRESS = "ADDRESS"; PASSPORT_RU = "PASSPORT_RU"
    SNILS = "SNILS"; INN = "INN"; PHONE = "PHONE"; EMAIL = "EMAIL"
    CARD = "CARD"; BIRTH_DATE = "BIRTH_DATE"

@dataclass(frozen=True)
class Context:
    project_id: str         # граница vault
    source_id: str          # документ/диалог: "file:<sha256 пути>" | "conv:<id>"
    mode: Literal["marker", "realistic"]

@dataclass(frozen=True)
class EntitySpan:
    start: int
    end: int
    type: PiiType
    raw_text: str
    detector: str                      # "regex:snils@1", "natasha@1.6"
    confidence: float | None = None    # None = не измерено
    grammemes: dict[str, str] | None = None   # {"case": "gent", "gender": "femn"}

# Роль 2. Spans не пересекаются и отсортированы по start.
# Пересечения разрешает detect: структурированный тип > NER, затем более длинный span.
# Checksum не сошлась → данные всё равно чувствительные (тип сохраняется, confidence ниже).
def detect(text: str, ctx: Context) -> list[EntitySpan]: ...   # raises DetectError

@dataclass(frozen=True)
class Replacement:
    start: int; end: int              # диапазон в ВЫХОДНОМ тексте
    entity_id: str                    # uuid4 из vault, не ФИО
    form: str | None                  # граммемы формы, если склонялась

@dataclass(frozen=True)
class MaskResult:
    text: str
    replacements: list[Replacement]

# Роль 3.
def mask(text: str, spans: list[EntitySpan], ctx: Context) -> MaskResult: ...  # raises MaskError

class RestoreStatus(StrEnum):
    COMPLETE = "complete"   # все известные псевдонимы восстановлены, подозрительных нет
    PARTIAL = "partial"     # есть неразрешённые ссылки (см. unresolved)

@dataclass(frozen=True)
class Unresolved:
    start: int; end: int
    reason: Literal["unknown_marker", "unknown_form", "ambiguous_form"]
    # без исходного текста ПДн: в логи попадает только reason и диапазон

@dataclass(frozen=True)
class RestoreResult:
    text: str
    status: RestoreStatus
    unresolved: list[Unresolved]

def restore(text: str, ctx: Context) -> RestoreResult: ...
```

Правила:

- **Сущность.** Ключ — `entity_id`, а не строка. Тёзки остаются разными сущностями.
  Упоминание связывается с существующей сущностью, если совпадает полная нормализованная форма
  **в том же `source_id`**. Иначе создаётся новая сущность. Неполное упоминание («Иванов», «И. Иванов»)
  связывается, только если в этом `source_id` ровно один кандидат. Иначе это новая сущность
  с флагом `ambiguous` (видна в просмотре таблицы).
  Связывание между документами — отдельное открытое решение (§10).
- **Псевдоним (режим realistic).** Тот же род и тот же тип склонения, что у оригинала.
  Соответствие форм «оригинал ↔ псевдоним» должно быть **взаимно однозначным** по всем падежам
  (контрпример «Саша Шевченко»). Если однозначности нет, генерируем другой. Если не нашлось —
  маркер. Псевдоним не совпадает ни с одним исходным значением в vault и в текущем тексте.
- **Restore.** Ищет только известные псевдонимы и маркеры проекта. Неизвестные метки и формы
  не угадываются. `PARTIAL` блокирует запись файла по политике (§6) и помечается в UI.
- **Структурированные данные.** В режиме realistic фиктивный номер сохраняет формат.
  Валидная контрольная сумма нужна только там, где задача проверяет формат **[предложение]**.

## 5. Адаптер Anthropic Messages (роль 1)

| Поле запроса | Действие |
| --- | --- |
| `system` (строка или блоки `text`) | mask |
| `messages[].content` блоки `text` | mask |
| блоки `tool_result` → `content` (строка или `text`) | mask |
| блоки `tool_use` в истории (`input`) | mask строковых значений рекурсивно |
| `thinking` / `redacted_thinking` | не трогать: подписаны провайдером, пришли уже с псевдонимами |
| `image`, `document`, неизвестные типы | **отказ** (MVP только текст) |
| `tools[]` (описания инструментов) | без изменений |

| Событие ответа (SSE) | Действие |
| --- | --- |
| `text_delta` | restore с буфером хвоста: задерживаем не больше `max_len(псевдоним)` символов, отдаём до последней границы слова |
| `input_json_delta` | копим весь блок, на `content_block_stop` парсим JSON, применяем политику §6, отдаём одним delta |
| `thinking_delta`, `signature_delta` | пропускаем без изменений |
| прочие (`message_start`, `ping`, ...) | пропускаем |

Без стриминга (`stream: false`) — то же на целом ответе. Ретраи и ошибки провайдера
передаются клиенту как есть.

## 6. Политика tools [предложение]

Реальные данные подставляются в аргументы, только если инструмент действует локально
и результат остаётся в разрешённой области.

| Инструмент Claude Code | Восстанавливать аргументы | Условие |
| --- | --- | --- |
| `Read`, `Glob`, `Grep` | да | путь внутри workspace |
| `Write`, `Edit` | да | путь внутри `allowed_write_roots`, не синхронизируемая папка; `restore` = `COMPLETE` |
| `Bash` | **нет** (псевдонимы как есть) | в MVP shell запрещён или ограничен allowlist-командами в sandbox |
| `WebFetch`, `WebSearch`, MCP-инструменты | **нет** | по умолчанию запрещены настройками Claude Code |
| неизвестный инструмент | **нет** | логируем имя инструмента |

Нарушение условия: вызов не восстанавливается. Модель получает `tool_use` с псевдонимами,
а gateway пишет событие аудита. Принудительно запретить вызов может только harness
(permissions / hook `PreToolUse`), поэтому эти настройки входят в поставку (§8).

## 7. Vault (роль 3)

- SQLite по пути `~/.local/share/<app>/vault/<project_id>.db`, вне workspace, права `0600`.
  Каталог не монтируется в sandbox агента (включая файлы `-wal` и `-shm`).
- Таблицы (эскиз): `entity(entity_id, project_id, type, ambiguous)`,
  `surface(entity_id, side, form, text)` — формы оригинала и псевдонима,
  `mention(entity_id, source_id, start, end)`.
- Шифрование на диске — после MVP **[предложение]**. В MVP защита держится на правах доступа и sandbox.
- Очистка: `purge(project_id)`.
- Кэш `mask` по хэшу блока — только после замера задержки. Ключ кэша включает версию
  детектора, политику, `project_id` и ревизию vault.

## 8. Sandbox и поставка (роли 4 и 1)

- Claude Code запускается так, что из сети доступен только `host:port` gateway.
  Конкретный механизм (network namespace, bubblewrap, sandbox Claude Code) выбирает роль 4 **[проверить]**.
- Фоновый трафик Claude Code вне gateway отключается по документации LLM gateway **[проверить]**.
- Агенту недоступны vault, конфиг и код gateway.
- В поставку входят: `settings.json` для Claude Code (`ANTHROPIC_BASE_URL`, запреты `WebFetch`,
  `WebSearch` и `Bash`), скрипт запуска sandbox и команда просмотра таблицы.
- Аутентификация: API-ключ пользователя у gateway. Работа через подписку не обещается **[проверить]**.

## 9. Gate и проверки

**Gate (первый шаг, фиксированный срок, синтетика):**

1. Gateway в режиме пропуска пишет в лог полные запросы и ответы (только на синтетике).
2. Сценарий: чтение файла → `Edit` → новый файл → повторный ход.
3. Видно, как Claude Code передаёт историю, `tool_result` и есть ли соединения мимо gateway.
4. Сбой фильтра → запрос не ушёл. Попытка сетевого вызова из sandbox → заблокирована.

Если пункт 3 или 4 не выполняется — сужаем обещание (Issue #4) до начала основной разработки.

**Метрики MVP:**

| Что | Как | Владелец |
| --- | --- | --- |
| Поиск | recall/precision по типам на размеченной синтетике, включая опечатки | 2 |
| Восстановление | `restore(mask(x)) == x`, плюс ответы, изменённые моделью: падежи, тёзки, неизвестные метки | 3 |
| Утечки | канарейки в исходящем трафике, наблюдение независимо от лога gateway | 4 |
| Полезность | маркеры vs псевдонимы vs оригинал: одна задача, несколько запусков, правильность писем и число правок | 1 + 4 |
| Практичность | задержка на ход, пиковая RAM, размер vault | 1 |

Ноль утечек на тестовом наборе — результат конкретной проверки, а не доказательство отсутствия утечек.
