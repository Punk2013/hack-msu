# Обсуждение: локальная защита данных для AI-агентов

Статус: обсуждение; формат, стек и объём MVP не утверждены.
Обновлено: 2026-10-25. Сводку ведёт IldwayS / Codex.
Общий разговор и предложения: [Issue #4](https://github.com/Punk2013/hack-msu/issues/4).

Это контекст для всех четырёх агентов, которым недоступна исходная переписка.
Документ сохраняет требования пользователя, варианты и ограничения.
Предложения ниже не означают согласия команды или поручения начать реализацию.
Ответы оставляем в Issue без PR; изменения сводки проходят обычный PR.
После выбора решения нужно обновить [паспорт проекта](PROJECT.md).

## 1. Что хочет пользователь

Обычный пользователь должен работать со своими данными через AI-агента,
не передавая исходные персональные данные внешнему провайдеру.
Например, номер паспорта не должен случайно попасть в запрос к облачной модели.
Желаемый процесс:

1. Локальная утилита получает исходные данные до обращения к агенту.
2. Она заменяет чувствительные фрагменты; агент работает с подготовленной копией.
3. После работы агента локальная утилита восстанавливает данные в результате.

Пользователь рассматривает любой удобный формат, включая плагин для Codex.
«Любые данные» — желаемое направление, а не согласованный объём первой версии.
Осведомлённость агента о заменах пока не определена.

Источник требований: обсуждение с пользователем 2026-10-25 (`user_reported`).

## 2. Главная нерешённая развилка

| Требование | Что из него следует |
| --- | --- |
| Можно отправлять проверенную копию с заменами, оригиналы остаются локально | Локальная обработка и восстановление; облачная модель видит оставшийся контекст |
| Никакое содержание документов не должно попасть иностранной компании | Локальная модель либо отдельно выбранная допустимая инфраструктура; контроль всех исходящих соединений |

Пользователь подчеркнул нежелание передавать свои данные иностранной компании.
Допустимость отправки обработанной копии ещё нужно уточнить; автоматически
считать такую отправку разрешённой нельзя.

Обратимые замены с таблицей соответствий — **псевдонимизация**.
Они не гарантируют анонимность: должность, даты, место и редкие обстоятельства
могут раскрывать личность. Удаление ФИО не скрывает смысл всего документа.
Отключение обучения на данных также не означает, что данные не передаются.

## 3. Варианты формы продукта

| Вариант | Плюсы | Ограничения |
| --- | --- | --- |
| Локальная утилита: подготовить и восстановить файл | Небольшой проверяемый MVP; можно использовать с разными агентами | Ручные шаги; пользователь может по ошибке передать оригинал |
| Локальное приложение со своим чатом | Контроль ввода, истории и показа результата | Нужно разрабатывать интерфейс и интеграцию с моделью |
| Плагин харнеса: локальный сервис + MCP + skill | Агент остаётся в привычном приложении; ядро можно переиспользовать | Защищает предусмотренный сценарий; прямое чтение оригиналов нужно технически исключить |
| Hooks в харнесе | Дополнительные проверки и блокировка некоторых действий | Покрытие зависит от событий и реализации; не универсальная граница защиты |
| Локальный API-прокси | Централизованная обработка запросов совместимых клиентов | Настройка endpoint; история, tools, streaming, вложения и обходные каналы усложняют реализацию |
| Расширение браузера | Привычный веб-чат | Зависимость от интерфейса сайта; сложнее покрыть файлы и все способы отправки |
| Skill без отдельного механизма изоляции | Простая установка инструкций | Модель может получить оригинал до выполнения инструкции или прочитать его другим инструментом |

Для расширения исходный текст нужно обрабатывать до его попадания в поле
стороннего сайта. Для прокси нельзя считать покрытым трафик, который идёт
мимо настроенного endpoint. Это инженерные ограничения, а не результаты тестов.

## 4. Что выяснено о Codex

По официальной документации, прочитанной 2026-10-25 (`verified_now` для документации):

- Плагин может включать skills, MCP-серверы и lifecycle hooks [S1].
- Есть плагины с локальным MCP-сервером по stdio [S2]. Плагин не обязательно облачный.
- При работе с облачной моделью переданные ей сообщения и результаты инструментов
  покидают компьютер. Локальность выполнения инструмента этого не меняет.
- `UserPromptSubmit` описывает блокировку сообщения и добавление контекста;
  документированной прозрачной замены исходного prompt не найдено [S3].
- Hooks покрывают не все инструменты; документация прямо не считает их полной
  границей защиты. Установка плагина также не означает доверия его hooks [S1, S3].
- Codex CLI поддерживает локальные провайдеры Ollama / LM Studio через `--oss` [S4].
  Этот факт не доказывает отсутствие других сетевых обращений.

Плагин не устанавливался и не тестировался. Поддержка конкретной версией клиента,
порядок обработки вложений, синхронизация, логи и сетевое поведение не проверены.
Нельзя обещать: «после установки любые данные в Codex автоматически защищены».

## 5. Предлагаемый сценарий плагина

Предложение ассистента (`hypothesis`), ещё не решение команды:

1. Пользователь импортирует документ в отдельном локальном окне, до передачи в чат.
2. Локальный движок, включая OCR при необходимости, находит чувствительные данные.
3. Пользователь видит «что отправится наружу» и исправляет пропуски или лишние замены.
4. Агент получает непрозрачный ID документа и читает только подготовленный текст.
5. Модель обрабатывает текст с согласованными заменами, например `[PERSON_1]`.
6. Локальный экспорт восстанавливает данные в файле для пользователя.
7. Агент получает безопасный статус готовности, без восстановленного содержимого.

Условные инструменты: `read_sanitized(document_id)` и
`export_restored(document_id, sanitized_result)`. Это эскиз, не утверждённый API.
Один ID должен соответствовать одному человеку в пределах выбранного контекста.
Явные маркеры проще отслеживать, чем вымышленные имена; их формат пока не выбран.

Оригиналы, таблица замен и готовый восстановленный файл должны быть недоступны
обычным инструментам чтения, терминалу и другим каналам агента.
Одной инструкции в skill или хранения «в другой папке» недостаточно.
Способ изоляции ещё предстоит выбрать и проверить.

Если передать исходный паспорт в чат с просьбой обезличить, защита запоздает.
Если вернуть восстановленный текст в MCP-ответ, историю, превью или лог,
он может снова попасть модели. Имена файлов и сообщения об ошибках тоже
могут содержать чувствительные сведения.

## 6. Что уже существует в open source

Ниже — результаты прежнего обзора в этой сессии (`historical`), а не аудит
или измерение качества. Перед выбором зависимости перепроверить лицензию,
состояние проекта, работу с русским языком и сетевые обращения.

| Проект | Чем полезен для сравнения | Лицензия по обзору |
| --- | --- | --- |
| [Presidio](https://github.com/data-privacy-stack/presidio) | Поиск PII и преобразования; возможная основа движка | MIT |
| [DocCloak](https://github.com/WLojek/DocCloak) | Локальная обработка документов в браузере, замены и восстановление; близкий конкурент | AGPL-3.0 |
| [PII GUI](https://github.com/sophia486/pii-gui) | Локальный интерфейс обнаружения и редактирования PII | AGPL-3.0 |
| [LLM Guard](https://github.com/protectai/llm-guard) | Anonymize / Vault / Deanonymize; в обзоре отмечен архив с 2026-07-09 | MIT |

Сам цикл «заменить → обработать моделью → восстановить» уже существует.
Это ограничивает заявление о новизне простой обёртки над готовым фильтром.

Возможные отличия, которые ещё надо обосновать: российские документы,
поиск косвенных идентификаторов, минимальное раскрытие под конкретную задачу,
наглядное сравнение оригинала и отправляемой копии, открытый стенд проверки утечек.
Ранее обсуждавшийся «контекстный двойник» сам по себе не доказывает новизну.

## 7. Связь с хакатоном

По слайдам пользователя: оригинальность 25%, польза 20%, работоспособность 20%,
качество исполнения 15%, командная работа 10%, использование AI 10%.
Источник: фотографии критериев от 2026-10-25 (`user_reported`); это не заключение жюри.

Предполагаемое соответствие — направление «Open Source × AI»; тему доверия
можно раскрыть проверкой того, что действительно отправляется модели.
Соответствие конкретной номинации и оценка оригинальности не подтверждены.

Предложение для демо: один сценарий и один-два формата, например текст и CSV
или текстовый PDF; выбор ещё не сделан. Показать полный цикл на синтетическом
документе и отправленный запрос. Универсальный OCR, видео и все форматы
не считать обязательствами MVP без отдельного решения.

## 8. Предлагаемые проверки MVP

Это критерии для обсуждения; проверки ещё не выполнялись:

- На размеченных синтетических примерах измерить пропуски и лишние замены по типам PII.
- Проверить одинаковые сущности, склонения, повторения, таблицы и сохранение смысла.
- Проверить восстановление известных маркеров; неизвестные и изменённые маркеры
  не должны приводить к подстановке выдуманных оригиналов.
- Проверить отправляемый контекст, вложения, историю и служебные каналы на оригиналы.
- Попытаться прочитать оригинал и таблицу замен через альтернативные инструменты.
- Сравнить полезность ответа агента на исходной и подготовленной синтетической задаче.
- При ошибке обработки или неподдерживаемом формате не отправлять исходник автоматически.

Нулевые пропуски на тестовой выборке не доказывают отсутствие утечек на любых данных.
Реальные документы, персональные данные и таблицы соответствий в GitHub не сохраняем.
