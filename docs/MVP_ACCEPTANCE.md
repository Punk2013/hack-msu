# Минимальное решение и проверка результата

Задача MVP: агент читает две синтетические текстовые карточки, отправляет модели
текст с заменами и записывает файлы с исходными реквизитами. Один протокол —
OpenAI Chat Completions; четыре типа — ФИО, email, российский телефон и паспорт.
Режим по умолчанию — realistic; marker нужен как запасной вариант и для сравнения.

## Что упрощено

- Новое полное ФИО не связывается с человеком только по совпавшей фамилии или
  другой части имени. Поиск использует полный нормализованный ключ данного
  упоминания. Ранее зарегистрированные короткие ключи могут обслуживать
  последующие короткие упоминания; неоднозначный ключ получает отдельную сущность.
  Короткое имя, встреченное до полного, больше не служит основанием их объединить.
- Один entity_id может иметь несколько маркеров: каждый относится к точной
  исходной строке. Это сохраняет падеж, регистр и формат номера при восстановлении.
- Зарезервированный синтаксис `[PERSON_1]` и аналогичные префиксы во входном тексте
  вызывают MaskError до отправки провайдеру, включая текст без найденных spans.
  Универсальное экранирование и угадывание происхождения маркера не добавлены.
- Коллизия сохранённой пары вызывает ошибку; проигравшая запись больше не
  игнорируется молча. Схема БД и публичные сигнатуры не меняются.

Новые форматы документов, OCR, дополнительные модели NER, поддержка других
протоколов и универсальная кореференция не нужны для этого сценария.
Произвольные имена и косвенные идентификаторы остаются ограничениями детектора.
Совпадающее полное ФИО по принятому контракту всё ещё означает одну сущность.

## Воспроизводимые проверки

После установки зависимостей из PROJECT.md, из корня репозитория:

```sh
.venv/bin/python -m pytest tests/pseudo/test_restore_integrity.py -q
.venv/bin/python -m pytest tests/integration -q
.venv/bin/python -m pytest -q -rs
.venv/bin/ruff check
```

`test_agent_file_loop.py` запускает настоящий HTTP gateway и demo_agent с реальными
файловыми tools. Детерминированный тестовый провайдер получает только запросы gateway.
Четыре запроса: чтение двух карточек → запись двух файлов → повторное чтение
готовых файлов → завершение. Проверяются точные файлы, отсутствие исходных полей
во всех четырёх исходящих запросах, в том числе внутри JSON-аргументов инструментов.
Выполняются marker/realistic и stream/nonstream. Это проверка интеграции;
полезность ответа живой LLM она не измеряет.

Дополнительно проверяются отказ до upstream при входном маркере, предел шагов
агента, коллизия пары и размещение приватных файлов запуска вне workspace.
Исчерпание шагов агента теперь означает ошибку, а не успешное завершение.

Проверено 25.10.2026 на macOS arm64 / Python 3.12.14: 235 passed, 4 skipped.
Все четыре пропуска — Linux namespaces/bubblewrap; OS-изоляция на Mac этим
прогоном не проверена. 13 регрессий восстановления до исправления падали.

## Живое демо и границы готовности

```sh
# Нужна запущенная Ollama с заранее установленной моделью.
bash scripts/demo.sh qwen2.5:7b
```

Скрипт использует новую копию карточек и новый vault для каждого запуска. Каталог
запуска имеет права 0700, vault/дампы/отчёт находятся вне workspace агента. Данные
синтетические; скрипт сам по себе не включает Linux sandbox. Профиль bubblewrap
и команды запуска описаны в bench/README.md. Приватный каталог запуска сохраняется
для проверки результата; автоматически не удаляется.

После обновления существующего развёртывания используйте новый `PII_PROJECT_ID`:
ошибочно объединённые старым движком сущности не исправляются автоматически.
Старые БД не удаляются. Повторно отправляйте оригиналы, а не ранее маскированный текст.

На Mac этой проверки Ollama не установлена и порт 11434 недоступен. Для приёмки
на Linux нужны запуск с реальной моделью и sandbox, содержательные уведомления
для обоих клиентов, проверка адресатов/реквизитов и независимый отчёт upstream
с положительным контролем утечки. Нулевые совпадения на тестовых данных не дают
гарантии отсутствия всех персональных данных. До этих проверок готовность
живого демонстрационного сценария не заявляется.
