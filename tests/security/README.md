# Независимые регрессии gateway, задача #9

Набор подготовила IldwayS после ревью PR #16. База: main `c35470e`,
gateway `3e8db0c`. Только вымышленная канарейка, `httpx.MockTransport`,
без ключей и внешнего трафика. Production-код не изменён.

```sh
.venv/bin/pytest tests/security -q
```

На указанной базе ожидается **11 failed, 2 passed**. Это draft PR с воспроизведением,
не готовое исправление. Не сливать до устранения дефектов; `skip`/`xfail` нет.
Автор gateway исправляет production-пути в своей ветке; после синхронизации
этот набор должен позеленеть. Удаление теста не считается исправлением.

| Сценарий | Приоритет | Ожидаемый результат |
| --- | --- | --- |
| metadata/user/лишние text-part поля/legacy function_call | P1 | отказ или обработка до upstream; исходной канарейки в запросе нет |
| Ключи JSON Schema и arguments | P1 | отказ или обратимая безопасная обработка; ключ не пересылается как есть |
| EOF / DONE без завершения choice; length / content_filter | P1 | накопленный write_file не выходит в поток; явная ошибка допустима |
| Многословный alias длиннее 64 символов | P2 | восстановление не зависит от места разреза входного потока |

Положительные контроли проверяют обычное маскирование и выпуск корректно
завершённого tool_call. Набор не должен проходить за счёт запрета вообще всех запросов.
В случае обрыва фиксируются уже выданные события: позднее исключение не скрывает
вызов, который успел уйти агенту.

P2 относится к заявленной поддержке realistic. Если команда вместо исправления
алгоритма исключит этот режим из streaming, нужен явный отказ на границе API
и отдельный тест ограничения. Это изменение контракта, а не доказательство
корректности текущего `_safe_cut` для произвольных псевдонимов.

Другие поверхности (sandbox, vault, реальные клиенты, сетевой трафик ОС) этим
набором не проверены. Название «регрессии» не означает полное покрытие продукта.
